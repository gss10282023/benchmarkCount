# 提示.md：Codex 与 GPT Pro 协作提示词

本文档用于从当前项目开始，严格按照 `工程文件说明.md` 完成 Step 1 到 Step 12。使用方式是：每个 Step 先把对应 **Codex 提示词** 发给 Codex；Codex 完成后会生成 `reviews/packets/...review_packet.md`；然后只把该 packet 给 GPT Pro 审查；若 GPT Pro 返回 `BLOCK_NEXT_STEP`，把审查结果交回 Codex 修复同一 Step，不进入下一 Step。

工作目录固定为：

```text
/Users/gss/Downloads/revised_agent_benchmark_paper_package
```

最高约束文件固定为：

```text
revised_agent_benchmark_paper.tex
计划.md
实验说明.md
工程文件说明.md
configs/agents.yaml
configs/infra.yaml
experiments/experiment_manifest.yaml
experiments/paper_mapping.md
```

## 0. 通用规则

### 0.1 给 Codex 的通用要求

每次给 Codex 的 Step 任务都必须包含：

```text
严格按照 /Users/gss/Downloads/revised_agent_benchmark_paper_package/工程文件说明.md 执行。
只做当前 Step，不进入下一 Step。
不得使用旧 scaffold、mock_result、dry-run 作为正式实验逻辑。
不得写入真实 API key、SSH private key 或其它 secret。
不得硬编码 Agent A-D、contract_drafter、judge_only 的 model IDs、version pins、temperature、prompt version 或 prompt hash；这些值必须从 configs/agents.yaml 和 locked manifest 读取，缺失或不一致时 fail closed。
所有 domain id 必须使用 canonical identifiers：agentdojo、appworld、webarena_verified、tau3_retail、androidworld、workarena、osworld_verified、judge_only、maintenance_update、matched_budget_controls；display name 只能作为展示字段。
job/result schema 必须区分 phase、experiment_type、priority：phase=smoke|dry_run|preflight|full|rerun；experiment_type=main|appendix|diagnostic|audit|maintenance_update|matched_budget_control；priority=P0|P1|P2|P3。
必须区分 record_slot、attempt、final_attempt、completed_record、infra_exclusion_record；evidence-envelope denominator 只用 completed scored records，denominator audit 覆盖 attempted record_slots 和 infra exclusions。
所有 UNRESOLVE R1-R7 必须使用固定 taxonomy：R1 Missing state query；R2 Unobservable side effect；R3 Ambiguous identity mapping；R4 Required state-preservation evidence absent；R5 Paired-arm asymmetry；R6 Evaluator output ambiguity；R7 Claim-scope mismatch。
INFRA_EXCLUDED 不得带 SUCCESS/FAIL/UNRESOLVE evidence_label，不进入 evidence envelope denominator，但必须进入 denominator audit。
COUNTED_ONLY_SCORE 在 SUCCESS+FAIL==0 时必须显式 undefined/null 并带 no_counted_records reason。
stronger_measurement 不得进入 native-aligned main envelope，且必须有 sidecar / appendix / manifest mapping。
scorer 不得默认使用 raw_run.native_label 或 summary scalar 作为 decisive evidence；native evaluator output 只有通过 locked artifact mapping、artifact manifest path/sha256/provenance 和 verified object/direct artifact read 才能 decisive。
pairwise_equality_tolerance、P1-P4 阈值边界、bootstrap plan、audit sampling plan、rerun subset 必须在正式 scoring 前冻结；interval touching threshold 默认 inconclusive，除非预先冻结 inclusive rule。
完整系统 scope 包括 P0/P1/P2/P3；declared appendix/diagnostic 缺失时必须阻止 paper outputs，除非论文文本和 manifest 已同步修改。
正式逻辑必须在 src/evidence_system/；scripts/*.py 如存在只能是 thin wrappers。
每个 Step 完成后必须生成对应 GPT Pro review packet。
完成后运行该 Step 能运行的自检，并报告结果。
```

### 0.2 给 GPT Pro 的通用要求

GPT Pro 不审整个项目，只审 Codex 生成的 review packet。GPT Pro 网页端不能读取本地路径，所以你要把 packet 文件内容完整复制给 GPT Pro。

**原则：只复制 review packet，不复制整个项目。**  
前提是 Codex 生成的 packet 必须自包含：它必须把本 Step 需要审查的论文、`计划.md`、`实验说明.md`、`工程文件说明.md` 摘录直接放进去。不能只写“见某某文件路径”。如果 packet 不自包含，让 Codex 先修 packet。

GPT Pro 输出必须固定为：

```text
# GPT Pro Review: Step XX

## Blocking Issues
## Non-Blocking Issues
## Alignment Evidence
## Required Fixes
## Decision
ALLOW_NEXT_STEP 或 BLOCK_NEXT_STEP
```

只有满足以下条件才能进入下一 Step：

```text
Decision: ALLOW_NEXT_STEP
并且 Blocking Issues 为空
```

### 0.2.1 GPT Pro 网页端到底复制什么

每次给 GPT Pro 的最小材料：

```text
1. 当前 Step 的 review packet 全文
2. GPT Pro 输出格式要求
```

不要默认复制整个 `revised_agent_benchmark_paper.tex`、`计划.md`、`实验说明.md`。这些文件太长，会拖慢审查。正确做法是让 Codex 在 review packet 里放本 Step 需要的摘录。

如果 GPT Pro 说证据不足，再让 Codex 生成补充 packet：

```text
reviews/packets/stepXX_<topic>_supplement_packet.md
```

不要临时把整个项目丢给 GPT Pro。
